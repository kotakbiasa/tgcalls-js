# Advanced Features Reference Guide

This reference covers the Telegram Bot API specifications for Guest Mode, Managed Bots (programmatic bots), Bot-to-Bot interactions, and Telegram Passport.

---

## 1. Guest Mode

Guest Mode allows bots to answer queries or perform actions in chats where the bot itself is not a member. The user interacts with the bot on a temporary or guest basis.

### Guest Queries
A bot can be configured to receive guest queries. When a user interacts with a guest-enabled surface, the bot receives updates containing inline or guest-specific query payloads.

#### `answerGuestQuery`
Answers a query sent from Guest Mode or a guest-initiated interface.
* **Parameters**:
  * `guest_query_id` (String): Unique identifier for the guest query.
  * `result` (`GuestQueryResult` or similar payload): The response actions or visual cards to return to the user.

#### `SentGuestMessage`
Returned upon answering a guest interaction, containing info about the sent message (similar to `Message` but tailored for guest scopes).
* Fields include `message_id` and structural chat indicators.

## 2. Managed Bots (Programmatic Fleet Architecture)

Managed Bots allow "manager" bots to programmatically spin up, manage, and tear down child/customer bots. This enables SaaS systems and white-label bot fleets to operate programmatically without manually registering tokens via BotFather.

### Core Fleet Lifecycle Methods

#### `createBot`
Creates a new child bot programmatically.
* **Parameters**:
  * `name` (String): The display name for the child bot.
  * `username` (String): Desired username for the bot (must end in `bot` or `_bot`).
* **Returns**: A JSON response containing the child bot's metadata and its `bot_token` (used to initialize a separate Bot API instance for that client).

#### `deleteBot`
Deletes an active child bot.
* **Parameters**:
  * `bot_token` (String): The token of the child bot to be deleted.
* **Returns**: Boolean status of the deletion request.

## 3. Bot-to-Bot Interaction Rules

By design, Telegram bots cannot see or interact with messages sent by other bots in group chats to prevent infinite loops of automated messages. However, under specific conditions:
1. **Direct Message**: Users can forward a message from one bot directly to another, or click an inline button that starts a deep link conversation in another bot.
2. **Inline Mode**: A bot can trigger inline queries that fetch results generated by another bot if the search is routed properly.
3. **Guest Mode Interactions**: Cross-bot interactions are strictly governed by user consent and sandboxed updates to ensure security and prevent looping.

## 4. Telegram Passport

Telegram Passport is a unified authorization method for services that require personal identification (KYC/AML). Users can upload their documents once, then share them securely with bots.

### Secure Flow
1. **Request Data**: The bot requests passport data using an inline button containing a `Passport` configuration.
2. **Decrypting Data**: Data is encrypted using the user's password and a public key provided by the bot.
3. **Passport Data Update**: The bot receives a `passport_data` (`PassportData`) object upon user approval.
4. **Decryption on Bot Server**: The bot uses its private key to decrypt the user's personal details and credentials.

### Objects

#### `PassportData`
* `data`: Encrypted personal data fields (`EncryptedPassportElement`).
* `credentials`: Encrypted credentials required to decrypt the data.

#### `EncryptedPassportElement`
* `type`: Element type (e.g., `personal_details`, `passport`, `driver_license`, `identity_card`, `address`, `utility_bill`, `bank_statement`, `rental_agreement`).
* `data`: Base64-encoded encrypted data.
* `front_side` / `reverse_side` / `selfie`: Encrypted files containing documents or photos.
